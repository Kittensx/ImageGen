# ImageGen Changelog — 2026-08-28

This update is a large alpha development snapshot covering Asset Browser/download-management work, prompt-parser reconstruction, LoRA runtime architecture, replay/output metadata, queue reliability, Hires prompt inheritance, live telemetry, and reusable workspace UI behavior.

> [!IMPORTANT]
> ImageGen remains alpha software. Some capabilities in this update are explicitly experimental. In particular, the **Asset Browser / Asset Hub checkpoint and LoRA download workflow is under active bug testing**, and **brace-based prompt grouping is still being revised**.

## Asset Browser / Asset Hub — Experimental

The provider-neutral Asset Hub has expanded into a full Asset Browser workflow, with Civitai as the first provider.

User-visible changes include:

- independent search tabs/sessions;
- optional pause of the previous provider fetch when a new search starts;
- preserving prior results and continuation cursors for later resume;
- simultaneous/resumed searches where provider/runtime behavior permits;
- continuous or manual provider paging;
- a persistent local discovery index and local faceted filtering;
- preview staging so resolved cards are published in small batches instead of racing metadata far ahead of images;
- provider/local preview distinctions and maturity-aware preview presentation;
- detailed model/version/file inspection;
- provider gallery caching and retention controls;
- Saved for Later assets;
- download history and source-detail navigation; and
- managed download/classification/installation into configured library roots.

### Download Manager

The managed downloader now includes configurable simultaneous-transfer limits, queue limits, bandwidth throttling, provider request spacing, retry limits, pause/resume/cancel controls, restart recovery, stale-partial cleanup, transfer history, size verification, and SHA-256 verification.

Interrupted downloads can reuse verified partial bytes when a correct HTTP Range continuation and source-identity/integrity checks prove the resume safe. Unsafe or ambiguous continuation is restarted instead of blindly appending data.

Verified downloads can automatically continue into classification and safe library finalization. Unknown, unsafe, or ambiguous files can be quarantined rather than guessed into a live model directory.

**Status:** experimental and under active bug testing. Users should keep backups of important model libraries and verify newly installed checkpoint/LoRA assets.

## Prompt Parser Improvements

The structured prompt parser has received substantial semantic reconstruction work.

Current changes include:

- typed numeric meaning by grammar context rather than generic integer/decimal guessing;
- `::` relationship scopes and `:::` owner-sequence scopes;
- structural `!` / `!!` terminators consumed by the parser instead of leaking into encoder text;
- schedules and alternates resolved deterministically against the active pass step count;
- recursive/nested parent-scope preservation;
- explicit model-family conditioning capability contracts;
- parser-neutral PromptIR/conditioning records;
- semantic digests and exact-replay validation;
- Prompt Inspector semantic-structure reporting; and
- model-free parser qualification plus an opt-in real-checkpoint image qualification path.

### Brace grouping remains under revision

Brace syntax and group-local numeric weights are recognized, but the intended grouping behavior is **not considered finished**. The design goal is to bind grouped concepts more closely as a related semantic unit than ordinary comma-separated concepts. Current testing found that the implemented conditioning behavior does not yet reproduce that goal reliably enough.

Grouping therefore remains experimental while the conditioning behavior is revised. Additional binding operators are being evaluated and are not claimed as current features until implemented and tested.

## LoRA Runtime and Compatibility

The standard adapter architecture layer now distinguishes denoiser/text-encoder targets by model family:

```text
SD1   -> UNet + TE1
SD2   -> UNet + TE1
SDXL  -> UNet + TE1 + TE2
SD3   -> Transformer + TE1 + TE2 + TE3
```

The user-visible LoRA weight contract is normalized so **`1.0` means the adapter's normal/native effect after loader-internal rank/alpha normalization**. User values scale that native effect instead of exposing internal format-specific scaling constants.

ImageGen also strengthens adapter inspection/classification so unsupported algorithms or potentially unsafe legacy serialized formats can be reported/restricted instead of being passed blindly through the standard loader.

### SD3 / SD3.5 LoRA status

The SD3-family target mapping is architectural groundwork only. **SD3 / SD3.5 LoRA application is not currently claimed as supported**, because a suitable real adapter has not yet been available for controlled end-to-end testing. Future qualification may require creating controlled LoRA test assets.

## Output, Replay, and Image Metadata

Generated images can now be saved as:

- PNG; or
- lossless WebP.

Images can embed **full replay metadata** or **compatibility-oriented metadata**. PNG uses embedded PNG metadata. WebP uses XMP for the full replay payload plus EXIF-compatible parameter text; if full WebP XMP cannot be persisted by the active runtime, compatibility metadata is preserved and ImageGen reports the fallback.

Image Details/replay inspection has also been expanded to present replay-essential information more clearly, including base/final dimensions, Hires state, and embedded-metadata availability.

## Hires Prompt Inheritance

Leaving the Hires prompt blank continues to mean **inherit the current base prompt**.

The WebUI/runtime state handling has been corrected so cancellation, editing, replay, or starting a later generation does not allow a prompt copied from an earlier request to remain as a stale hidden Hires override when the user intended inheritance.

## Queue and Runtime Reliability

Queue/runtime hardening includes:

- cancelling paused queued jobs even when they have no live worker attached;
- cancelling restart-recovered held jobs without waiting for a nonexistent runtime process;
- preventing late/buffered runtime events from reviving cancelled work;
- stronger cancellation handling around runtime/model-load retry paths; and
- watchdog accounting that avoids treating computer sleep/event-loop suspension as ordinary generation-stall time.

## Live Preview and CFG Telemetry

Base generation and Hires refinement now carry clearer pass identity through live preview/sampler tracing. Step counts and effective CFG telemetry can transition into the Hires pass without conflating base-pass and second-pass trajectories.

## Workspace Components and Asset Details

The shared workspace component system now supports persistent component resizing through drag/keyboard controls.

A reusable overlay capability adds:

- right-side drawer presentation;
- focused/lightbox-style presentation;
- resizable drawer width;
- click-outside and Escape collapse; and
- an edge restore tab so minimized/collapsed overlays remain recoverable.

Asset Details is the first major consumer, but the behavior is implemented as a reusable shared-container capability.

## Configuration / Managed Asset Roots

The user configuration and managed-root registry now include explicit locations for:

```text
TextEncoders
control-lora
Upscalers_ComfyUI
```

These paths make the assets discoverable/manageable by the project architecture. The presence of a managed path does **not** by itself claim that every corresponding generation workflow is currently supported; for example, a `control-lora` path should not be read as a ControlNet/Control-LoRA generation support announcement.

## Documentation Status

This release also formalizes a distinction between **Available**, **Available — alpha**, **Experimental**, **Unverified / qualification pending**, and **Planned** capabilities. See `features/EXPERIMENTAL.md` for implemented areas that are still receiving active bug testing or qualification.

## Prompt Parser - Legacy BREAK Unification

The production Legacy Default prompt profile now maps uppercase `BREAK` to the typed `CHUNK_BREAK / encoder_chunk_break_v1` runtime. This reuses the model-family BREAK contract qualified for SD1, SDXL, and SD3/SD3.5 instead of retaining a separate legacy text/special-case path. Legacy `AND`, grouping, and the rest of the production grammar are unchanged. The profile version advances to `3`; source-only historical replays may therefore use the corrected BREAK behavior, while stored semantic records/profile snapshots remain distinguishable.
